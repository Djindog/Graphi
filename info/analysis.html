1
Learnability
The core mechanic is invisible
1.1
Problem The defining feature — blue nodes on the canvas represent the active context window — is never explained. A new user sees blue nodes appear, doesn't know what they mean, and can't connect the canvas to what the AI receives. The 3-stage pipeline (type → curate → send) has zero onboarding.
Solutions
  • One-time walkthrough overlay on first use explaining the 3 stages
  • Inline ghost text in the input: "Nodes highlighted on canvas = context sent to AI"
  • Dismissible banner in chat pane on first node selection
Grip level is unexplained jargon
1.2
Problem "Grip off/low/mid/high" is meaningless to new users. There is no explanation that it controls RAG retrieval depth, what "off" means (no semantic search), or what the tradeoff between levels is.
Solutions
  • Tooltip on hover: "Controls how many semantically similar nodes are pulled into context from across your project"
  • An info icon (ⓘ) next to the Grip label
  • Alternative label: "Recall: None / Broad / Focused / Precise"
Swipe gestures are fully undiscoverable
1.3
Problem Vertical overscroll to create a new child node, horizontal swipe to navigate siblings — powerful features with no affordance, hint, or tooltip. A user will never find them accidentally.
Solutions
  • Subtle animated arrow at the bottom of chat scroll area when at the bottom: "↓ Swipe to branch"
  • First-use tip shown once after first message is sent
  • Keyboard shortcut hint visible in the input bar footer
Node operations are hover-only, no right-click
1.4
Problem The context menu (branch, rename, fold, cut, prune, transplant) only appears via the ··· hover button. Right-click is not supported. No visual cue that nodes are interactive beyond clicking.
Solutions
  • Support right-click to open the same context menu
  • Faint "right-click or ···" hint on first hover of a node
2
Feedback & System Status
Stage 0 context detection runs silently
2.1
Problem When the user types, reference detection and RAG run in the background with no visible indicator. The canvas update can lag 500ms+ with no feedback. The user doesn't know if the system is working or stuck.
Solutions
  • Subtle pulsing ring or spinner on the input border while Stage 0 is active
  • Small "Analyzing…" microtext near the Grip controls during detection
No micro-feedback when context nodes are toggled
2.2
Problem Clicking a blue node to deactivate it fades it on canvas silently. The interaction is quiet and can feel accidental.
Solutions
  • Micro-animation on the dot indicator in ContextSummary when toggled (pulse or color flip)
  • Transient count badge: "3 of 5 context nodes active" near the context panel header
Snapshot save is completely invisible
2.3
Problem After every generation, a snapshot is auto-saved to Supabase. The user has no idea this happened, what was saved, or that snapshots exist at all.
Solutions
  • Subtle "Saved" microtext or checkmark that fades in/out after save completes
  • Sets correct expectations for future snapshot browsing features
Auto-generated title change is unexplained
2.4
Problem After the first message, the node title is silently updated by AI. The user sees the title change in the canvas but has no explanation of why or when.
Solutions
  • Brief highlight or fade transition on the node when its title changes
  • A subtle tooltip: "Title auto-generated from your first message"
3
Navigation & Spatial Orientation
No way to re-center on the selected node
3.1
Problem After panning/zooming the canvas, there is no button to re-center on the active node. The user must hunt manually.
Solutions
  • "Center on selected node" button in the canvas toolbar
  • Auto-center when active node changes
Switching layout modes loses spatial memory
3.2
Problem Switching between tree and force modes rebuilds the full layout. In force mode, physics drift makes it impossible to build a reliable mental map.
Solutions
  • Persist force-mode node positions across mode switches
  • Consider a "manual" layout mode where users can pin positions
No breadcrumb / lineage path in chat pane
3.3
Problem The chat pane header shows only the current node title. There is no breadcrumb showing the path from root to the current node (e.g., "Root > Design > UI Exploration"). Context about where you are in the tree is lost.
Solutions
  • Collapsible breadcrumb trail above the chat header
  • Hovering over the node title shows ancestors in a tooltip
No project name visible when sidebar is collapsed
3.4
Problem When the sidebar is collapsed (48px wide), the active project name disappears entirely. The user sees only the canvas and chat with no orientation landmark.
Solutions
  • Show active project name in the canvas toolbar when sidebar is collapsed
  • Or a small label above the tree/force mode toggle
4
Context Management (ContextSummary Panel)
Context panel appears abruptly, pushing content
4.1
Problem The ContextSummary panel appears between the node header and message list, pushing the message list down with no animation. Especially jarring during fast typing since Stage 0 fires 500ms after the keypress.
Solutions
  • Animate the panel in with a smooth height transition (max-height CSS transition)
  • Consider a slide-in from above that overlays rather than displacing content
Section labels "Lineage / Referenced / Recommended" are unexplained
4.2
Problem The three context categories are meaningful to the developer but opaque to users. "Lineage" especially — that it means all ancestors back to root — is non-obvious.
Solutions
  • Add (ⓘ) tooltips on each section label
  • "Lineage: parent nodes back to root" / "Referenced: nodes you mentioned by name" / "Recommended: semantically similar nodes"
Toggle affordance in the chip list is ambiguous
4.3
Problem The ● / ○ dot indicator is 7px and the hover state is only a background tint. It's not obviously a toggle control.
Solutions
  • Use a larger, more iconographic indicator (checkbox, eye icon, or strike-through on inactive)
  • Show explicit tooltip: "Click to exclude from context" / "Click to include"
No way to manually add arbitrary nodes to context
4.4
Problem Context is limited to lineage + detected references + RAG recommendations. A user who wants to manually include a specific node can't — they would have to mention it by name in their message.
Solutions
  • "Pin to context" option in the node's ··· menu — forces it into active context for the next send
  • A search/autocomplete input in the ContextSummary panel to manually add nodes
5
Chat Pane UX
No visual transition when switching nodes
5.1
Problem Switching nodes replaces the message history instantly. There's no animation indicating the context shifted, which can be disorienting.
Solutions
  • Brief fade or slide transition on the message list when switching nodes
  • Small "Switched to: [Node Title]" system message at the top of the new thread
Empty state for new nodes provides no orientation
5.2
Problem "Type to start this thread…" is minimal. For a newly branched node, the user has no context about where they are relative to the parent.
Solutions
  • Show parent node's last message or summary: "Branched from: [parent title] — [last message excerpt]"
  • Include a "View parent thread" link in the empty state
Send button and Stop button are separate confusing controls
5.3
Problem During generation, the send button shows a spinner but the stop control is a separate circle that appears next to it. Two simultaneous buttons for one action is confusing.
Solutions
  • Transform the send button into a stop button during generation (single control, dual state) — the common pattern in modern chat UIs like Claude, ChatGPT
  • Or enlarge the stop button with a clear label on first appearance
Textarea is fixed height, wastes space for short inputs
5.4
Problem rows={3} is always 3 rows tall regardless of input length. This wastes vertical space in the already constrained chat pane for typical one-line queries.
Solutions
  • Auto-resize textarea to fit content, starting at 1 row and growing to a max of 6
No copy button on assistant messages
5.5
Problem There is no way to copy an assistant message other than manually selecting text. This is a baseline affordance in every modern chat UI.
Solutions
  • Show a small copy icon on hover over assistant message bubbles
  • Alternatively, copy the raw markdown text (not rendered HTML)
6
Node Operations (NodeToolOverlay)
Destructive operations are one click away with no undo
6.1
Problem "Delete Subtree" (prune) shows a browser confirm() dialog. "Remove (Keep Children)" (cut) executes immediately with no confirmation at all. Both are irreversible with no undo path.
Solutions
  • Add a confirm step to the "cut" operation (currently missing)
  • Replace browser confirm() with a custom in-overlay confirmation — "Are you sure? This can't be undone" in the app's visual language
  • Add a brief undo toast: "Subtree deleted — Undo" (5-second window) that can reverse the operation
"Remove (Keep Children)" is confusing terminology
6.2
Problem Users expect "delete" to remove everything. This operation splices the node out and re-parents children, which requires understanding the data model to predict the outcome.
Solutions
  • Rename to "Splice out" or "Remove node only" with a sub-label in a tooltip
  • Move the parenthetical explanation to a hover tooltip rather than the button label
Overlay Y-clamp uses a fixed height estimate
6.3
Problem The Y-axis clamp uses a hardcoded value of 260px for the overlay height. If the overlay grows (e.g., transplant submenu with many projects), it can overflow at the bottom of the screen.
Solutions
  • Measure the actual rendered overlay height and use that for clamping
  • Or apply a max-height with internal scroll on the content area
7
Sidebar
Pinned projects are lost on page refresh
7.1
Problem Pinned projects are stored in useState. They are lost on every page refresh. This is a fake feature that sets false expectations of persistence.
Solutions
  • Persist pins to localStorage as a quick fix
  • Or persist to the profiles table in Supabase for true cross-device persistence
Collapsed sidebar loses all project management affordances
7.2
Problem When collapsed to 48px, only the ☰ hamburger icon is shown. There is no way to create a project, switch projects, or access user settings without reopening.
Solutions
  • Icon-only quick actions in collapsed state (+ icon for new project)
  • Consider a hover-expand sidebar (like VS Code) instead of full collapse
No search when there are many projects
7.3
Problem With many projects, there is no way to search or filter. Users must scroll the full list.
Solutions
  • Search input appears at the top of the project list when there are more than 8–10 projects
  • Or a Cmd+K command palette for project and node search
Project deletion uses a native browser confirm() dialog
7.4
Problem The browser's native confirm() dialog is visually inconsistent with the rest of the app's design language and cannot be styled.
Solutions
  • Replace with inline confirmation inside the project menu (button turns red, second click confirms)
  • Or use the existing modal pattern with a custom compact confirmation variant
8
Visual Design
Monochrome palette lacks personality and warmth
8.1
Problem The app is entirely neutral — dark text, white/gray backgrounds, generic Tailwind blue for state. For a "thinking partner" tool, warmth and personality matter for retention and perceived quality.
Solutions
  • Introduce a subtle accent color distinct from the generic #2563EB blue
  • Micro-animations on node creation and branch formation add delight without changing the palette
Canvas background is a flat, featureless gray
8.2
Problem The tree floats on a plain #F0F2F5 background with no visual grounding. The canvas feels empty and unpolished compared to tools in the same category (Miro, Figma, n8n, Obsidian Canvas).
Solutions
  • Subtle dot-grid or cross-grid pattern on the canvas background — industry standard for node editors
  • A very faint radial gradient from center to edges gives depth without adding noise
Force mode nodes are too small to read or click accurately
8.3
Problem 11px radius circles with 10px font labels are very hard to read and require precise pointer placement. Force mode is effectively less usable than tree mode.
Solutions
  • Increase node radius to 14–16px minimum
  • Use 11–12px font in force labels
  • Or use rectangular nodes in force mode for visual consistency with tree mode
No dark mode support
8.4
Problem The app is hardcoded to white/light backgrounds. There is no dark mode support, which is a standard expectation for productivity tools used for extended periods.
Solutions
  • CSS custom properties (already partially present) would allow a single-variable theming switch
  • Not urgent for MVP, but the inline-style architecture makes it harder to add later
9
Accessibility
Canvas interactions require a pointing device
9.1
Problem The D3 SVG canvas has no keyboard navigation (beyond the swipe arrow-key gestures). Users cannot tab through nodes, open the context menu with keyboard, or navigate the tree without a mouse or trackpad.
Solutions
  • tabindex and aria-label on D3 node groups
  • Arrow keys to move selection between nodes (parent/child/sibling)
  • Enter/Space to open the context menu on the selected node
Color is the only indicator of context node state
9.2
Problem Active context = blue, deactivated = faded blue, non-context = gray. For users with color vision deficiencies, these three states may be indistinguishable.
Solutions
  • Add a secondary indicator: dashed border for deactivated nodes, solid for active
  • Or use stroke patterns (e.g., strikethrough, hatching) as a secondary signal alongside color
Focus states on interactive elements are invisible
9.3
Problem All buttons and inputs have outline: 'none', suppressing standard browser focus rings. Tab navigation has no visible indicator.
Solutions
  • Restore :focus-visible with a custom box-shadow (e.g., 0 0 0 3px rgba(37,99,235,0.4))
  • Audit all interactive elements for focus visibility
10
Performance & Responsiveness
D3 tree is fully rebuilt on every state change
10.1
Problem TreeCanvas runs svg.selectAll('*').remove() and rebuilds the entire SVG tree whenever any node, style, or context state changes. For large trees this causes perceptible redraws with a flash/relayout.
Solutions
  • Separate structure/layout pass from the style pass — ForceCanvas already does this with two effects
  • Apply the same two-effect pattern to TreeCanvas: rebuild only on node array changes, restyle on visual state changes
Canvas layout does not respond to window resize
10.2
Problem The D3 canvas captures container dimensions once on mount. Resizing the browser window does not re-layout the tree, leaving it misaligned.
Solutions
  • Add a ResizeObserver on the container div to trigger re-layout when dimensions change
No loading state when switching projects
10.3
Problem Selecting a project triggers a Supabase fetch. During this fetch, the canvas goes blank or shows stale nodes with no loading indicator.
Solutions
  • Show a spinner or skeleton in the canvas area during project load
  • Optimistically keep the old nodes visible while new ones are fetching
